Keep project context true.

Overseer is a repo-local Agent Skill that reconciles AI-facing documentation with repository reality, then applies only owner-approved context and file-hygiene changes.

scan audit clean
Plain-language promise: every AI agent starts with clean, current project context.

Product boundary

A project caretaker, not another orchestrator

The host agent supplies judgment and conversation context. A deterministic local kernel owns filesystem evidence, safety, approval binding, recovery, and verification.

Overseer does

  • Detect stale, duplicated, missing, and ambiguous context.
  • Maintain one root overseer.md ledger.
  • Repair approved living documentation and Markdown references.
  • Rename, move, and archive exact approved files.
  • Journal, verify, and recover every mutation.

Overseer does not

  • Create invoices, reports, images, CSV data, or other outputs.
  • Rewrite business artifacts or source code.
  • Permanently delete project or archive content.
  • Run agents, schedule itself, or watch in the background.
  • Require a UI, account, service, network, or paid API.

Public vocabulary

Three modes, one approval boundary

Default

scan

Lightweight session-close check over changed, created, and referenced paths plus a bounded ownership and link closure.

May prepare only an approved ledger update.

Periodic

audit

Bounded repository-wide evidence inventory with complete, partial, or limit-exceeded coverage.

Partial evidence never authorizes mutation.

Approval-gated

clean

Dry-run-first remediation grouped into Documentation, Organize, and Archive with visible forced dependencies.

Only exact dependency-closed approval can apply.

Safety contract

The kernel has less authority than a general shell

Mutation primitives
5
Ledger, policy, living doc, exact move, exact archive
Permanent project deletes
0
Archive remains owner-managed
Network calls
0
Offline standard library runtime
Standing approvals
0
Every plan binds exact state
Untrusted content: repository text is inert evidence. It cannot grant approval, change policy, or request tool use.
Concurrent edits: every forward and reverse operation revalidates identity and hashes. Unexpected state is never overwritten.
Secrets: no secret excerpts, values, or full protected paths enter previews, ledger, journals, manifests, or errors.
Recovery: exact preimages survive only until verified completion or conflict-aware recovery.
